# Омегабуд

Багатосторінковий сайт ремонтних послуг, керування портфоліо, заявками й аналітикою.

## Збірка

```sh
npm ci
npm run build
npm test
```

Netlify бере команду й каталог публікації з `netlify.toml`: `npm run build`, `dist`. Дев’ять посадкових сторінок генеруються з `data/services.mjs`, шаблони — `scripts/build.mjs`. Головна `index.html` синхронізується під час збірки. Вихідні `dist/` та залежності не комітяться.

## Панель `/admin/`

Використовується наявна авторизація Supabase й RPC `is_site_owner`. Сервер **кожного разу** перевіряє власника через Supabase, не довіряючи перевірці в браузері. Жодного service-role ключа немає. Вхід — наявним обліковим записом власника; створення акаунта й зміна пароля не реалізовані.

Розділи:
- Об’єкти й фото: чернетки, публікація, обкладинка, напрямок, до 12 фотографій; автоматичне зменшення в браузері до 1800 px, до 2 МБ після обробки. Завантажені зображення доступні за прямим посиланням; прибирайте приватні дані до завантаження.
- Заявки: останні 1000, телефони, деталі, статуси та видалення з підтвердженням. Поштові повідомлення **не підключені**: перевіряйте панель.
- Аналітика: 7/30/90 днів, сеанси зі згодою, перегляди, джерела, покази карток, переходи й успішні заявки, таблиці за днями та послугами. Максимум 20000 подій на звіт, скорочення вказується в інтерфейсі. Дати агрегуються за UTC.
- Налаштування: заголовок, опис, фото першого екрана й GA4 Measurement ID.
- Архів редактора: старі Supabase `site_pages` та редактор GrapesJS збережені. Їхнє збереження в базі **не замінює** статично згенеровані публічні сторінки. Це чітко підписано в панелі.

## Зберігання

Netlify Functions + `@netlify/blobs` із site-wide сховищами: `omegabud-content`, `omegabud-leads`, `omegabud-events`. Сховища створюються SDK під час першого запису в Netlify; записи зберігаються між публікаціями. Для фотографій/заявок не потрібна ручна SQL-міграція. Netlify Functions і Blobs повинні бути доступні для поточного проєкту/тарифу. Секретів Netlify у коді немає. У локальному статичному preview API не працює — використовуйте unit/integration tests або Netlify dev для повного виконання серверної частини.

Публічний API: опубліковане портфоліо, фотографії, приймання заявок та подій. API власника: читання заявок, статистика, зміна портфоліо й налаштувань. Доступ перевіряється сервером. POST вимагає same-origin, застосований IP rate limit Netlify, пастка для ботів, перевірка формату фото та довжини вхідних даних. Публічні аналітичні події — спостережувані дії, не фінансовий облік і не антифрод-система.

## Аналітика

Збирається після добровільної згоди; Do Not Track враховується. ПІБ і телефон у події не потрапляють. Конверсія = унікальні сеанси із серверно підтвердженою заявкою / сеанси з переглядом сторінки. Заявки без згоди зберігаються, але не входять до аналітики. Натискання телефону не є підтвердженим дзвінком. Повторне надсилання форми з тим самим requestId протягом доби не створює дубль. Планова функція `cleanup` видаляє події старші за 90 днів.

GA4 вмикається після додавання ідентифікатора в панелі й згоди відвідувача. Подія `generate_lead` відповідає успішній заявці. Покази в Google, пошукові запити й кліки з пошуку потребують окремого підтвердженого ресурсу Search Console. Автоматичний імпорт Google Search Console/Google Ads у панель не підключений. Лічильник «покази карток» не підміняє покази в Google.

## Контент

Не додано вигаданих об’єктів, відгуків, цін, строків, стажу чи гарантій. Портфоліо з’явиться після публікації перших реальних об’єктів у панелі. За відсутності фото перший екран містить підписану SVG-ілюстрацію; фото першого опублікованого об’єкта замінить її автоматично. Потрібно окремо додати фактичні кейси, прайс/діапазони за реальними даними та справжні відгуки.

Перед рекламою: перевірити вхід власника на робочому домені, створити тестовий об’єкт із власним фото та надіслати контрольну заявку. Видалити контрольну заявку в панелі. Прив’язати власний домен і оновити `base` у генераторі, якщо домен зміниться.

## Заявка на кошторис

`/koshtorys/` — окрема форма у два кроки. Параметр `?service=<id>` обирає послугу зі сторінки, з якої прийшов відвідувач. Збираються вид і опис робіт, площа або позначка про невідому площу, одиниця площі, населений пункт, район, тип об’єкта, ім’я й телефон. Дробова площа приймає кому та крапку.

За бажанням можна прикріпити до 3 файлів загальним розміром до 4 МіБ: PDF, JPEG, PNG, WebP. Форма надсилає multipart одним запитом після згоди. Вкладення зберігаються в приватному сховищі заявок, не в публічній медіатеці. Сервер перевіряє кількість, загальний розмір, розширення й початкові байти формату; це не антивірусна перевірка. Завантаження з панелі вимагає токена власника в заголовку, файли віддаються як attachment з no-store. Токенів у посиланнях немає. Видалення заявки видаляє й її файли.

Ліміт 4 МіБ обраний з урахуванням буферизованих запитів/відповідей Netlify Functions. Для більших планів потрібен окремий механізм прямого завантаження. Автоматичної оцінки ціни форма не робить: кошторис узгоджується після опрацювання заявки.

## Типи об’єктів і види робіт

Публічний каталог розділено на «Об’єкти» (квартири, офіси та комерційні приміщення) і «Види робіт» (стяжка, натяжні стелі, штукатурка, малярні, плиткові, гіпсокартонні та демонтажні роботи). Усі попередні URL збережено. Єдина класифікація для API, панелі й сайту — `assets/catalog.js`.

Портфоліо має незалежні поля `objectType` та `workTypes[]`. На одному об’єкті можна позначити кілька виконаних робіт. Фільтри за об’єктом і видом робіт застосовуються разом. На посадкові сторінки об’єкт потрапляє за відповідною класифікацією без дублювання записів.

Старі записи з одним полем `service` читаються зі збереженням наявної класифікації: ремонт квартир → квартира, комерційний ремонт → комерційне приміщення; окрема стара послуга → відповідний вид робіт. Конкретний тип комерційного об’єкта та додаткові виконані роботи не визначаються з назви чи фотографій. Збережені записи не перезаписуються під час публікації коду. Власник може уточнити класифікацію в редакторі об’єкта.

## Позначки виду робіт для кожного фото

У редакторі об’єкта під кожним фото є «Види робіт» із кількома позначками. Збереження об’єкта записує `photoWorkTypes` — відповідність URL фото масиву відомих видів робіт. Ключі URL зберігають позначки під час зміни обкладинки та порядку; вилучені фото більше не мають активних позначок. Порожній масив означає показ лише в загальній галереї об’єкта. У галереях окремих робіт і під час фільтрування показуються лише відповідні фото; обкладинкою стає перше з них.

Старі записи без фото-позначок зберігають попередній показ за напрямками об’єкта. При редагуванні ці позначки доступні під кожним фото й можуть бути уточнені. Старий клієнт, що не надсилає `photoWorkTypes`, не стирає вже записані позначки. Публікуються лише фото опублікованих об’єктів. Вибір позначок набуває чинності після «Зберегти об’єкт».
